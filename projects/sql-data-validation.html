PROJECT 07 · DATABASE TESTING

FICTIONAL DATASET · SQL EVIDENCE

SQL Data Validation

QA-focused SQL against a fictional HR/payroll dataset, demonstrating data validation, reconciliation and defect investigation rather than SQL in isolation.

What I validate

Employee and payroll relationships, duplicate business keys, orphaned transactions, missing expected records, NULL/reference-data gaps, payroll calculations and aggregate reconciliation.

SQL demonstrated

SELECT · WHERE · ORDER BY · INNER/LEFT JOIN · GROUP BY · COUNT/SUM/AVG · HAVING · CASE · subqueries · CTEs · NULL checks.

Example — find calculation mismatches

SELECT payroll_id, gross_pay, deductions, net_pay,
       gross_pay - deductions AS expected_net_pay,
       net_pay - (gross_pay - deductions) AS variance
FROM payroll_transactions
WHERE net_pay <> gross_pay - deductions;

Controlled defects

The seed data intentionally includes a duplicate employee number, an orphan payroll record, a net-pay mismatch, missing department data, an active employee without payroll and an inactive employee with a payment. This makes the queries produce reviewable QA evidence.

Data safety

All names, values and records in this project are fictional. No employer, client or production data is used.
